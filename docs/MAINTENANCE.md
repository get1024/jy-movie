# 维护与迁移说明

## 策略

本次采用保留接口与数据结构的增量重构，而不是同时改写三个前端和整个 Java 后端。目标是修复可验证的业务缺陷、增加回归保护，并让后续迁移有稳定基线。

- Vue 2.7 与 Element UI 2 继续保留；构建工具升级到 Vue CLI 5 / Webpack 5，使用 Node 24
- Spring Boot 2.7 / Java 11 作为兼容性过渡基线；这不是长期受支持平台的最终方案
- 提交 npm 锁文件，以 `npm ci` 重现依赖安装；不再跟踪编译产物与个人 IDE 配置
- GitHub Actions 分别验证后端和三个前端，只有读仓库权限，不部署、不上传产物

## 主要行为变化

- 请求发送时读取当前 token，避免登录后仍使用旧 token；统一网络/超时提示并保留原业务响应格式
- 购物车结算处理全部选中条目，区分“稍后支付”和关闭对话框，并防止重复点击
- 海报成功提交后清空表单和上传状态，避免连续上传复用旧数据
- 待支付订单满 15 分钟后失效；定时任务每 60 秒检查，查询/抢座/支付路径也进行过期处理
- 只有未过期待支付订单和已支付订单占座；创建订单在数据库事务内锁定场次，金额根据场次价格与座位数重新计算
- 支付和撤销采用条件更新，避免过期任务覆盖已支付状态；这些仍是演示支付行为
- 订单、购物车及相关展示数据使用有界批量查询，降低逐条读取关联数据的开销
- JWT 主体与角色正确保留，签名密钥来自环境变量；密码字段不再随 JSON 响应返回
- 公开浏览页面继续可用，其他 API 默认要求登录；这不替代后续接口级角色和数据归属治理
- 上传完整读取文件内容，读取失败返回错误而不是生成空链接；可配置外部图片服务地址

## 升级前后检查

1. 备份数据库与应用配置，确认能恢复旧版本
2. 在测试环境使用数据库副本，配置 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`JWT_SECRET`
3. `JWT_SECRET` 必须由部署人员设置为独立随机的至少 32 字节字符串；缺失或过短应拒绝启动。不要在仓库、截图、工单或命令日志中泄露真实值
4. 新版本不会继续使用源码里原来的签名密钥。所有终端清除旧 token 并重新登录，确认用户、员工和管理员都可登录
5. 单独构建并部署三个前端；`VUE_APP_API_URL` 在构建时注入，修改后需要重新构建
6. 确认服务器时区与原数据库日期字符串的解释一致。历史订单时间没有时区信息，不能在迁移时随意切换服务器时区
7. 在测试数据库验证：不同用户抢同一座位、待支付订单到期、重复支付、管理员撤销、多条购物车结算、上传海报后继续上传
8. 历史路由使用 HTML5 history 模式；静态站点服务器必须将未知前端路径回退到对应 `index.html`，同时让 `/api` 走后端

本次不自动修改用户的部署环境，也不自动生成或保存真实密钥。

## 安全与上线限制

### 仍需专项处理

- **授权与对象归属**：身份验证不等于完整授权。仍需对每个接口实现和测试用户、员工、管理员的角色约束，以及订单、购物车、资料等对象的归属校验。不得仅依赖前端隐藏菜单
- **公开资料与账号生命周期**：公开评价/留言仍可能嵌套完整用户资料（已去掉密码），需进一步改为最小公开 DTO；JWT 中的角色直到过期前不会自动同步权限变更，用户名也缺少数据库唯一性约束。原管理员演示账号首次成功登录会升级为 BCrypt 存储，但演示密码仍必须更换
- **真实支付**：当前支付只是演示状态变更。接入真实支付前必须服务端校验支付平台签名、金额、订单归属、回调幂等和退款状态，不能信任客户端传入的“已支付”状态
- **旧框架**：Vue 2 / Vue CLI / Spring Boot 2.7 已处于旧版本阶段。补丁升级和移除个别有风险依赖不能替代 Vue 3、受支持 Spring Boot/JDK 及相关生态迁移
- **历史公开数据**：Git 历史与 SQL 演示快照可能包含原项目的账号数据、哈希和其他示例个人数据。删除当前源码中的密钥不会删除历史；如曾用于真实系统，应由维护者轮换历史密钥/凭据并评估数据清理。本次不改写 Git 历史
- **上传与部署**：上传大小、文件类型与内容验证、存储隔离、反向代理、HTTPS、跨域白名单和限流仍需按实际部署完善。上传链接默认仍指向本机；远程部署应设置 `APP_PUBLIC_URL` 为外部服务根地址（不含 `/api`），并验证反向代理路径
- **数据库与并发**：单元测试不能证明生产 MySQL 的事务隔离、连接配置、索引和多实例行为；部署前进行集成与并发测试

### 后续建议顺序

1. 完成接口级 RBAC、对象归属校验和安全集成测试
2. 增加独立 MySQL 测试环境，覆盖抢座、订单到期、管理员操作和浏览器端到端流程
3. 将历史字符串日期及金额迁移为明确时区的时间类型与精确金额类型，配套向前/回滚迁移
4. 分别推进 Vue 3 + Element Plus 与受支持的 Spring Boot/JDK，避免一次性大迁移无法定位回归
5. 评估数据库图片存储、分页、缓存与索引；基于实际数据规模做性能测量

## 依赖审计与开发服务

本次依赖锁定后，三个前端各自的 `npm audit --omit=dev` 仍报告 2 个低危项（Vue 2 及其下游关联）；完整开发依赖审计各为 16 项：4 高危、10 中危、2 低危。审计结果会随公告数据库更新变化，可在各目录重新运行 `npm audit` 确认。

没有用 `npm audit fix --force` 强行跨大版本改写依赖，因为这可能破坏旧构建链。ECharts 已升级并启用兼容主题以消除当次发现的图表相关问题。开发服务器仅供本机开发，不应暴露到公网；生产请部署 `npm run build` 生成的静态文件，并按受支持技术栈迁移计划处理剩余风险。

## 验证范围

自动检查侧重单元回归、依赖可安装性、Java 打包和三个生产前端构建。它们不覆盖真实数据库连接、历史演示数据的完整性、真实支付、所有角色权限，以及真实浏览器的完整购票验收。

具体本次通过的测试数量和线上 CI 结果以对应提交的 Actions 记录为准。不要把一个局部测试或单次构建通过理解为“全部业务、安全和生产部署均已验证”。
